# T11｜统一所有卡片的答案校验

日期：2026-10-25。状态：本地实现与专项验收完成，未部署。

## 已完成

从计分流程提取统一的 `answer-validation.js`，所有卡片在计算任何分数前，均按事件创建时冻结的题目、选修配置和适用状态校验。`processAnswers` 只在校验通过后计分；开始接口的题目 `validation` 元数据也由同一模块生成，供 T20 页面使用。

修复两类实际错误：

- HTTP JSON 的极端数值（例如 `1e400`）会被解析为 Infinity。此前在生成幂等指纹时提前报409“计分依据不合法”，无法保存正常拒绝记录。现在使用独立请求指纹处理，返回422并保存原子拒绝回执；同键改变为 null 或其他值仍被拒绝。
- 不合法 JSON 请求此前被四评路由包装为500。现在返回400 `XG_BAD_PARAM`，不改写事件。

请求指纹对所有有限 JSON 数据与 T10 完全一致；题库及历史计分依据仍使用原有严格哈希，不允许非有限数值。没有修改计分公式、量程或历史版本数据。

## 校验口径

| 输入/题型 | 处理 |
| --- | --- |
| answers 外形 | 必须为题号到值的普通对象；null、数组、字符串、数字和布尔值均返回422 |
| 必答项 | 每个适用题必须显式提供；缺字段/null返回 `XG_MISSING_ITEM`，field指向题号，不补0或5 |
| slider | 仅数值类型的0–10整数，含0/10；小数、字符串、布尔值、数组、对象及非有限数值拒绝 |
| d1 | 只接受数值0、1、2；字符串选项不做隐式转换 |
| p6（第二节起） | 只接受数值0、5、10；必须提供 |
| p6（首节） | 可省略或传null；任何实际值均拒绝。保存时不生成p6，完整对照分仍为null |
| o1 | 必答、非空白字符串，上限沿用T09的2000个UTF-16代码单元；原文及换行保留，不自动trim、不计分 |
| 未开启的s8–s10 | 不在冻结题面中，传入即 `XG_UNKNOWN_ITEM`，即使值为null也不静默丢弃 |
| 已开启的s8–s10 | 整组必答，缺任何一题拒绝；不改变核心七题量程 |
| 未知/其他卡片题号 | 整份拒绝，不忽略、不存储额外字段 |
| 低耗时或同分 | 答案本身合法则接受，并沿用low质量标记，不能当作校验失败 |

文本长度继续使用现有JavaScript字符串计数口径：普通汉字计1，常见表情如😀计2；这项说明用于接口一致性，不是本次新增产品限制。接口 `validation` 对文本明确返回 `max_length:2000`、`non_blank:true`、`length_unit:"utf16"`。滑条返回min/max/integer；单选返回允许的values。正文只作为文本保存，页面仍应按纯文本渲染。

如果发现不支持的题型或必填/适用状态矛盾，按依据错误停止处理，不把未知类型当滑条接受。

| 卡片/场景 | 必答内容 |
| --- | --- |

验证矩阵包含7种卡片、10种场景、全部42个题号。每一个适用题都验证了缺项与null，每一道滑条都验证了上下界和非法类型。选修改动后的提交仍依旧题面判定，开启→关闭和关闭→开启两个方向均已验收。

## 状态、回执与权限

沿用T09/T10：已经开始的事件校验失败返回422，并保存rejected状态、错误定位、修订审计及操作回执；不保存失败原始答案、不生成分数、不占成功名额、不改写基线或结案档案。

相同请求重试返回已有回执；同键更改答案返回409；修正答案使用新request_id，可在原事件上提交成功。拒绝及修正均保留同一冻结依据。来访端成功响应不包含分数、原始答案或完整basis。错误不会回显提交值、请求头或运行时凭据。

注意：随访之前已存在结案档案，拒绝随访的正确断言是“现有档案不变”，不是“结案档案不存在”。
