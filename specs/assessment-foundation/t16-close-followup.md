后续T17已接通发送worker、结果/重试/兜底与私人站内信；入队后的状态契约及发送前复核见 [T17说明](t17-notification-delivery.md)。

## 结案事务与时间口径

`closeMatch(match_id, session_no)` 现在在同一事务内完成：

- 校验真实周期与最终节次，保留既有结案卡/评价卡的一致性限制。
- 写入服务器closed_at、最终节次和closed状态。
- 释放当前双方的active周期占位，允许之后新建周期。
- 创建1m/3m两条确定ID的随访计划，并保存结案档案的两个due_at。

1m和3m均从**原始closed_at独立加1/3个自然月**，使用Asia/Shanghai（UTC+8）日历，保留当地时刻；目标月无对应日时取月末，不按30/90天计算，也不从已经夹取的1m日期继续加2个月。

例如2026-01-31 09:00结案，1m为2026-02-28 09:00，3m为2026-04-30 09:00。闰年1月31日加1个月取2月29日。存储统一使用UTC ISO时间，计划标识calendar-shanghai-v1。

同一周期/最终节次的重复结案只返回原记录，不重置日期、任务状态或已填数据。改变最终节次返回409；计划或档案写失败时整笔回滚。历史已结案但缺少计划的记录明确报错，不以当前日期补造计划；迁移需在T21单独核对。

新周期不接管旧计划。旧周期的随访继续引用原match_id、咨询师和最终节次，填答不会改写新周期基线或档案。

## 到期、同意与完成

随访新开卡和提交均校验原周期计划；到期前返回409 `XG_FOLLOWUP_NOT_DUE`，到期瞬间即可填写。无需先发过消息才能填写，页面和调度互不依赖。

使用followup用途的有效同意，包括当前必需版本。撤销同意后，待填卡片立即隐藏，新开卡/提交被拒绝，已开始尝试仍可放弃。再次同意不会重置原计划日期。

随访成功提交时，答卷、名额、档案、回执、计划completed状态及未发送任务取消处于同一事务。拒绝/放弃不消耗本轮成功名额，允许重新开始；已经sent的通知结果不被改写。1m/3m各自独立，一轮完成不代替另一轮。

本次不新增随访过期窗口，超过到期时间的未完成轮次仍按有效同意和采集开关处理。

## 持久化调度

新增2个私有集合，当前声明共30个：

| 集合 | 用途 |
| --- | --- |
| xg_followup_jobs | 每周期/轮次一份日历计划，保存原closed_at、due_at、next_check_at、检查结果与完成状态 |
| xg_notification_tasks | 确定业务ID的发送待办；本项只生产followup队列，T17接管发送 |

调度按status和next_check_at在数据库中筛选并分页，每批1–100条。每条计划在事务内重新读取周期、成功名额、同意和采集暂停状态，并检查作用域和原到期日期。

| 检查结果 | 处理 |
| --- | --- |
| 未到期 | 不入队 |
| 已有成功随访答卷 | 计划completed，取消未发送任务 |
| 无有效同意、同意书未配置、来访停用或collection_paused | 计划blocked；既有queued任务在重新检查时变为blocked |
| 合格且无发送任务 | 创建queued任务，记录授权依据、轮次、原周期和优先通道 |
| 已有同一queued任务 | 不重复创建或增加发送次数 |
| blocked后重新合格 | 恢复同一个任务ID，保留原计划日期 |
| 发送器已经接管（processing/failed/cancelled等） | 保留发送器状态，不冒充重试或覆盖结果 |
| 任务已有sent结果 | 计划标记notified，不再次发起发送 |

非终态计划检查后推迟24小时再次复核；扫描通过推进next_check_at处理下一批，不使用会因状态变动而漏行的offset。并发扫描仍只有一个业务任务ID。单条失败回滚并返回脱敏错误，其他条目可继续；失败计划保留重试机会。

**入队不等于触达。** 本项只写follow_*_queued_at；follow_*_sent_at及follow_*_result保持未发送，不因调度成功填成sent。通道顺序为miniprogram→inapp，不使用短信发送普通随访。

撤销同意或暂停后，已排队任务在下次检查时阻断；页面/作答入口即时执行当前守卫。T17发送器仍必须在真正发送前重新检查同意、采集状态和任务修订，不能只相信旧consent_ref或queued状态。处理中的外部发送及失败重试不由本项伪造完成。

紧急停止普通提醒并不自动取消随访采集：随访调度使用collection_paused，独立于enable_reminder/emergency_stop，符合T15“回滚保留采集与结评”的边界。

## 专用服务接口

### 匹配服务结案

`POST /v1/xg/m4/close`

```json
{ "match_id": "cycle-id", "session_no": 3 }
```

需要独立的XPG_MATCH_SERVICE_SECRET，以Bearer方式调用。返回200及原closed_at、最终节次、follow_scheduled、两轮due_at。时间和双方身份由服务端取值，拒绝客户端closed_at/user_id/counselor_id等字段。

### 外部调度扫描

`POST /v1/xg/jobs/follow-dispatch`

```json
{ "limit": 50 }
```

使用独立的XPG_SCHEDULER_SECRET。只允许批量上限，不允许调用者传入now、指定他人身份或绕过同意。响应是scanned/results/errors/more_possible，结果明确区分queued、already_queued、blocked、completed、notified等，不返回虚构sent数量。

两类secret须分别配置、至少32字节且不能相同；缺失/混用配置返回503，错误身份401。普通来访、咨询师及管理员登录会话都不能代替服务凭据，匹配凭据不能调用调度入口，调度凭据不能结案或进入普通用户API。响应no-store，不回显header、token或原始异常。

## 独立调度脚本

入口：[scripts/dispatch-followups.cjs](../../scripts/dispatch-followups.cjs)。

在外部任务执行器注入XPG_API_BASE及XPG_SCHEDULER_SECRET后运行：

```sh
node scripts/dispatch-followups.cjs
```

脚本使用独立HTTP调用，不依赖来访打开页面；默认每批20条，最多20批。出现服务/条目错误或达到批次上限后仍有工作，以非零退出码提示执行器重试。只输出计数摘要，凭据从环境注入，不写入代码、命令参数或日志。生产目标须HTTPS，测试允许本机HTTP；拒绝自动跳转，避免凭据跟随跳转。

建议由外部任务执行器每天09:00 Asia/Shanghai调用。**脚本及服务入口已经实现并完成本地端到端验证，但本次没有创建线上定时任务、配置真实secret或调用真实环境扫描**；这些资源在T21/T22联调部署时接入。执行环境需支持原生fetch（Node.js 18及以上）。

## 待填卡片接口

`GET /v1/xg/prompts/next?match_id=...&session_no=...`

已从占位响应接入实际读取：

- 来访未建基线时提示M0；已有基线后，首节默认M2，符合T12超过7天且首节前条件才追加M1重测；第2节起按实际session_no返回M1/M2。
- 咨询师按实际节次返回M3。普通会谈节次由调用方明确提供，不通过已有答卷数量压缩缺节。
- 活跃周期显式请求followup用途且提供最终节次时，可提示结案/评价卡；仍须有效followup同意。
- 已结案周期默认followup用途，返回尚未提交的结案/评价卡及已到期随访轮次，均使用原closing_session_no。
- 已成功提交的业务位置不再提示；缺少同意、来访停用或暂停采集时返回空列表；不能跨周期授权。

提示只返回周期、卡片、节次、轮次和时间，不返回分数。实际开始/提交仍再次检查资格，不能凭旧提示绕过新撤销或暂停。
