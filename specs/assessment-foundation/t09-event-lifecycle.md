## 已打通的行为

`/events/start`、`/events`、`/events/abandon` 已由占位的501响应切换为实际处理。开始、拒绝、成功提交及放弃均保存服务端时间与事件修订记录；拒绝不占成功提交名额，同一事件修正答案后可以成功提交。

| 当前状态 | 操作 | 结果 |
|---|---|---|
| 无事件 | start + 新 client_event_id | 新建 started，固定 T08 依据，返回实际填卡题目 |
| started | 答案校验失败 | 保存 rejected，返回422及错误题号，不占成功名额 |
| rejected | 修正后提交 | 同一事件转 submitted，保留原始开始时间、题目依据和拒绝历史 |
| started | 合法提交 | submitted，原子保存答案、服务端分数、名额、档案和状态历史 |
| started / rejected | 主动放弃 | abandoned，保存时间和原因 |
| started / rejected | 恢复/提交时发现已过期 | abandoned；提交返回409，不生成分数 |
| submitted | 同答案重试 | 返回已保存结果，不重新计分、不增加修订 |
| submitted | 修改答案或放弃 | 409，不覆盖已提交记录 |
| abandoned | 重复放弃 | 返回原结果，不改写最初原因 |
| abandoned | 再次提交 | 409；必须使用新开始标识重新填写 |

新开始标识可以为之前拒绝/放弃的同一业务位置创建新尝试，但同一位置仍只允许一份成功答卷。

## API 使用顺序

### 1. 开始填卡

`POST /v1/xg/events/start`

```json
{
  "match_id": "本次咨询周期",
  "scale_code": "xg_m0_baseline",
  "session_no": 0,
  "client_event_id": "本次尝试的新UUID"
}
```

首次成功返回201，包括 event_id、status、revision、started_at、expires_at 和 form。form 是本事件已经冻结的题目，包含实际题干、锚点、选项、必答/适用状态；不返回完整规则、阈值或原始 basis。

前端应使用返回的 form 展示填卡页，不能另取最新题库替换它。首节 M3 的 p6 标为不适用，不要求填写“持平”。

同一角色/身份的相同 client_event_id 定位同一尝试：相同卡片/周期/节次请求会恢复原事件，改变用途返回409。重复开始不会重新生成依据。终态返回原状态且 form=null，不重新打开填写。

### 2. 提交答案

`POST /v1/xg/events`

```json
{
  "match_id": "本次咨询周期",
  "event_id": "start返回的event_id",
  "client_event_id": "可选：必须与开始时一致",
  "answers": { "s1": 6 },
  "duration_ms": 40000
}
```

示例答案不完整，用于说明结构；实际必须按 form 补齐。event_id 必填，不支持绕过 start 的一键插入。可选的 scale_code、session_no、follow_round 如传入必须与原事件一致。

缺项、越界或其他答案错误返回422，例如：

```json
{
  "event_id": "…",
  "scale_code": "xg_m0_baseline",
  "status": "rejected",
  "revision": 2,
  "duplicated": false,
  "error": { "code": "XG_MISSING_ITEM", "field": "s3", "message": "请完成该必答项" }
}
```

拒绝状态先提交数据库事务，再返回422；不会因为在事务中抛出错误而抹掉拒绝留痕。拒绝记录只保留错误类型/题号和请求指纹，不保存非法答案值；客户端应保留本地输入供修正。

补全后继续提交同一 event_id。成功的来访响应只有状态、saved=true 和中性反馈，不含分数或原始答案；咨询师提交本人 M3 时可得到主分/百分比，首节为 null。

同答案重试使用规范化 JSON 的指纹判断，对象键顺序不影响判断。客户端耗时不是计分依据，因此仅改变 duration_ms 不会触发重算或改写成功答案。完整请求级幂等契约和真实并发验收仍归 T10。

### 3. 放弃或离开

`POST /v1/xg/events/abandon`

```json
{ "match_id": "本次咨询周期", "event_id": "本次事件", "reason": "page_leave" }
```

reason 支持 timeout / user_exit / page_leave，默认 user_exit。已撤销同意或周期已关闭时仍允许本人放弃尚未提交的尝试；这不会开放新数据采集。已提交记录始终不能被放弃请求覆盖。

## 同意、归属与事务边界

每次操作都核对可信会话、周期、角色及事件作者，不能跨来访/咨询师操作，不能修改已有卡片、节次或随访轮次。管理员不代填。

开始新的尝试、恢复可填写尝试、处理新提交时，使用 T07 的 `requireInTransaction()` 在同一个数据库事务内检查当前有效同意，并写入版本/状态锚点。M3 使用该周期来访的 assessment 同意；结案、服务评价和随访使用 followup。

开始时保存 start_consent，成功提交时保存 submission_consent。填写期间同意版本升级后，需要先重新同意当前版本；提交继续使用原先冻结的题目依据，同时记录新的提交同意引用。

已完成答卷的同答案重试只是返回历史结果，无新增采集，因此即使后来撤销同意也不重新写入或恢复授权。恢复仍可填写的旧尝试则必须通过当前同意检查。

成功提交的事务同时包含：同意锚点、有效提交名额、答案与分数、基线/结案/随访档案更新、状态修订及周期版本更新。任意一步失败整体回滚。不同尝试争用同一成功名额时，失败者保留原状态并返回冲突。

## 为成功流转接入的基础校验与计分

submitted 不能表示“只存了答案、以后再计分”。为使 T09 链路真实可用，新增确定性的 answer-processor，按冻结依据完成：

- 必答项、整数滑条范围、单选合法值、文本类型/长度、未知题号及不适用题检查，不补零。
- 七题核心分、ORS、附加分、补足分、资源分、解离档及各卡主分；M1 选修另存，不改变70分核心量程。
- 首节 p6 不适用时，M3 完整总分/百分比为空。
- 当前仅支持 xg-core-t03-v1；未知历史引擎返回503，不把系统能力不足当成用户答案错误，也不伪造分数。
- 首节 M1 重测成功前核对原始基线超过规定天数、尚无已提交的后续节次，并保留原始基线。

这部分是支撑 T09 的基础实现，不代表 T11/T12 已完成。42题全部边界用例、规则引擎版本管理、历史复算及完整基线时点验收仍在后续专项任务中。

质量标记使用服务端从开始到提交的总经过时间，客户端 duration_ms 只作为 client_duration_ms 留痕，不能通过虚报耗时影响质量判断。低于冻结阈值或数值答案全同值时标记 low，照常保存。

## 超时和审计

新尝试默认30分钟到期，具体 expires_at 在创建时固定。恢复或提交时触及到期边界，会把未完成尝试转为 abandoned。T18已补齐无人再访问的独立后台回收、并发幂等和到期耗时封顶；线上定时器尚未部署，当前契约见 [T18说明](t18-statistics-expiry.md)。

新增私有集合 xg_event_transitions，主键为 hash(event_id, event_revision)，保存前后状态、动作、作者、时间、依据哈希及校验错误题号。每次有效变化递增 event_revision；重复成功/放弃请求不增加历史。总集合声明数为21，客户端直接读写仍拒绝。

底层 insertEvent 保留为导入/测试原语；公开接口必须经 lifecycle 服务，不能绕过同意、角色和状态校验直接调用底层插入。
