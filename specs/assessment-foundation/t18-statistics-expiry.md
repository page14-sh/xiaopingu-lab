# T18｜统计口径与服务端超时回收

日期：2026-10-25。状态：本地实现与专项测试完成；未部署、未配置线上定时器、未修改真实数据库，也未发送真实消息。

## 交付范围

- 管理员聚合统计接口：`GET /v1/xg/admin/stats`。
- 独立超时回收接口：`POST /v1/xg/jobs/events-expire`，以及 `scripts/reap-expired-events.cjs` 调度入口。
- 按开始事实统计分母，区分尝试和业务位置；重试不重复计入同一位置。
- 小样本隐藏、服务端字段投影、固定维度查询和分页上限。
- 提醒首次触发元数据及首次 CST 时间，用于区分确认、处理和关闭。

沿用现有36个私有集合，无新增集合。`collections.json` 增加事件超时扫描索引，以及6个统计源的 `_id + 时间字段` 索引声明；这些索引尚未创建或在真实环境验证。

## 接口及日期

```text
GET /v1/xg/admin/stats?metric=all&from=2026-10-01&to=2026-10-25
```

仅有效管理员会话可读，来访与咨询师均无权限。参数只允许 `metric/from/to`，拒绝重复参数以及来访、咨询师、周期等个人筛选条件。响应和错误均 `Cache-Control: no-store`。

- `metric`：`all`（默认）、`fill_duration`、`abandon_rate`、`low_quality_rate`、`alert_handle_time`、`remind_action_rate`、`follow_return_rate`、`notifications`、`llm_success`。
- `from/to` 必须同时提供，格式严格为有效的 `YYYY-MM-DD`；最多366天，不接受未来日期。省略时为上海时区含今天的最近30个自然日。
- 日期按 `Asia/Shanghai`，首日00:00含、末日次日00:00不含。当天只统计到服务端本次生成报表的 `as_of`。
- 区间用于选取统计群体；其后续提交、回收、处理、通知回执可计至本次 `as_of`，所以历史区间的转化率可能随业务进展变化。这里不提供任意历史时刻的状态快照。
- 响应标记 `schema_version=stats-t18-v1`、时区、`as_of`、隐私规则与 `consistency=bounded_observed_read`。多集合读取不是全库事务快照；并发写入期间各页可能观察到不同进度，不能当作冻结审计报表。

## 分母、去重和指标

原包通过 `status='started'` 统计发起分母会漏掉已经提交或放弃的尝试。本实现以持久的 `started_at` 选取发起事实，后续状态变化不删除这个事实。

| 返回指标 | 群体和算法 |
| --- | --- |
| `attempt_counts` | 区间内开始的不同 `event_id`；列出总发起数、已提交、已放弃、待完成；rejected 属待完成 |
| `attempt_abandon_rate` | 上述群体中已 abandoned 的尝试数 / 全部发起尝试数 |
| `abandon_rate` | 业务位置首次开始于区间内的位置中，所有尝试均放弃的位置数 / 全部首次开始位置数 |
| `fill_duration_ms` | 区间内提交的事件，服务端 `duration_ms` 的 p50/p90，单位毫秒；采用连续分位数线性插值 |
| `low_quality_rate` | 区间内提交且质量标记已知的事件中 low / (low + ok)，不把 rejected 算作低质量提交 |
| `alert_handle_time_h` | 区间内首次触发的原始 L2/L3 提醒中，已关闭提醒的 `(handled_at-triggered_at)` p50/p90；分 outcome/alliance/stability/dissociation，单位小时 |
| `remind_action_rate` | 区间内首次触发的原始 L2/L3 提醒中，开始 CST 或已关闭 / 全部该群体提醒；按原始信号统计，展示降级或阶段开关不改写分母 |
| `remind_ack_rate` | 同一提醒群体中的已确认比例；单纯 ack 不算 CST 处理 |
| `follow_return_rate.1m/3m` | 区间内已到期的原周期、原轮次计划中，到期后已经真实提交随访卡的比例；包括尚未发送、被阻断的到期计划 |
| `follow_on_time_rate` | 返回 `not_available / return_deadline_not_defined`；T16 尚未定义到期后的填写截止窗口，因此不能声称是“按期率” |
| `llm_success_rate` | 返回 `not_available / llm_jobs_not_implemented`；任务状态分母留待 T19，不能用结果集合代替任务集合 |

业务位置直接沿用成功提交名额的身份：周期 + 卡片 + 有效节次位置 + 随访轮次。M0/M4/M5和每轮随访按周期唯一，逐节卡按节次唯一；不同周期互不合并。统计读取历史开始事实，以确定位置的真正首次开始时间，不能把区间内的新重试误当新位置。

例如：同一位置先放弃、后重新开始并成功提交，算2次尝试、1个位置，尝试放弃率为1/2，该位置放弃率为0。若第二次仍待完成，该位置也尚未终结为放弃。相同请求键重放返回原事件，不增加尝试；同事件被重复读取也只计一次。

旧记录没有可信 `started_at` 时不补造开始事实，也不进入上述事件统计。质量字段未知的提交不进入质量率分母。旧提醒没有 `triggered_at/initial_level/alert_type` 时不推测补齐，排除于处理统计；响应的 coverage 字段标记这一覆盖范围。T18 后新提醒原子保存这些首次元数据，重算、再次确认和后续 CST 不重置首次时间。

## 通知分别计量

`notifications` 按区间内创建的不同通知任务统计，发送重试不增加任务分母。

| 返回字段 | 计量事实 |
| --- | --- |
| `provider_accepted_rate` | 服务商明确 accepted、迟到 accepted 回执，或管理员证据核对为已受理；只有 sent_at 不算受理 |
| `inapp_stored_rate` | 已实际保存站内消息 |
| `delivery_confirmed_rate` | 服务商受理或站内消息入库的任务并集；同任务两个事实不重复计数，不代表用户已收到或阅读 |
| `unresolved_rate` | 当前仍为 uncertain 的任务；即使存在迟到受理证据，仍需管理员完成状态核对 |
| `inapp_read_rate` | 已入库站内任务中的明确 read_at 比例 |
| `external_read_rate` | `not_available / no_external_read_receipts`，不把服务商受理伪装为用户已读 |

咨询师 ack、CST 和关闭来自独立动作台账，不从发送记录推导。通知等待、失败或消息已读也不能代替随访卡成功提交。

## 聚合隐私与读取边界

1. 服务端只读取固定投影：业务标识、状态、时间、耗时、质量标记及规范化通知结果。原始答案、分数、备注、联系人、租约和服务商原始响应不进入统计读取器；标识仅用于内存去重，不进入聚合响应。
2. 每个指标至少覆盖5名不同来访。比例的非零分子和非零补集也各需至少5名不同来访；否则仅返回 `{status:'suppressed', reason:'insufficient_cohort'}`，不返回比例、人数或分子分母。五次同一人作答不能满足门槛。
3. 尝试状态摘要如任一非空子组不足门槛，则整组隐藏。分类型、分轮次和已读比例各自判断门槛。空群体隐藏，避免 NaN 或误导性的0%。
4. 每个源按 `_id` 游标读取100条一页，默认每源最多10,000条，超限返回503 `XG_STATS_TOO_LARGE`，不会静默截断后输出“完整”比例。SDK 错误或不递增游标亦失败关闭，不转为空报表。
5. 为正确计算位置首次开始，事件源读取截至 as_of 的历史事件投影；因此缩短报表区间不一定能避开事件源上限。超过规模需要离线预聚合/物化统计方案，不能仅凭本地测试承诺大规模性能。通知尝试和站内消息读至 as_of，以包含区间后的回执。

这是管理员权限下的小样本抑制，不是差分隐私；不承诺阻止跨报表、交叠区间的所有差分推断，也不能作为去标识后公开数据发布的依据。报表读取本身不回收事件、不发送通知、不改变业务数据。

## 超时回收

```text
POST /v1/xg/jobs/events-expire
Authorization: Bearer <XPG_SCHEDULER_SECRET>
Content-Type: application/json

{"limit":50}
```

只接受专用 scheduler 凭据，普通管理员/来访会话及 matching 凭据无权调用。只接受 `limit`（1–100，默认50），拒绝客户端时间、event_id 和查询参数。

- 服务端查询 `status in [started,rejected]` 且 `expires_at <= now`，按到期时间、ID排序；默认尝试到期时间仍为开始后30分钟，拒绝后修正不重置到期时间。
- 每个候选进入独立事务，再读事件状态、到期时间、周期归属及冻结依据。仅尚未完成且真正到期才写 abandoned/timeout；并发提交、主动放弃或另一回收者已经完成的记录跳过。
- 终态、修订审计及周期更新同事务提交，审计增加 `initiator=scheduler`。回收不创建或覆盖客户端请求回执，不写成功名额、分数、档案或发送任务。
- 实际 `abandoned_at` 记录处理时间；timeout 的 `duration_ms` 截至固定 `expires_at`，迟到一天清理不会把作答耗时算成一天。
- 撤销同意、关闭周期、暂停新采集不阻止已有尝试终结。前端主动请求 timeout 也必须达到服务端到期时间，提前请求返回409 `XG_EVENT_NOT_EXPIRED`。
- 单条失败回滚并返回安全错误码，继续处理本批其他候选；成功记录离开待回收集合，下一批无需 offset。坏数据可能持续占据批次，需根据错误修复，不能无限跳过而无声宣告全部完成。

响应包含 `scanned/results/errors/more_possible`。结果只含事件ID与 reaped/skipped；错误不包含原始异常内容或答案。重试和并发回收不会重复写终态审计。

独立执行入口（由运行环境注入 `XPG_API_BASE/XPG_SCHEDULER_SECRET`）：

```bash
node scripts/reap-expired-events.cjs
```

脚本每批20条，最多20批，只允许 HTTPS（本地回环 HTTP 用于测试），禁止重定向；输出计数摘要，不打印凭据或事件ID。发生错误或批次预算用尽且可能有剩余时退出码为1，由调度平台告警/重试。回收扫描建议每5分钟执行；30分钟是资格边界，实际终结时间还取决于调度间隔和服务可用性。本次仅交付入口，没有安装或启用线上定时器。
