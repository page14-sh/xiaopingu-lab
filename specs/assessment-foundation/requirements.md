## 2. T01：技术路线

### 2.1 已确认选择

沿用 CloudRun + Node.js + CloudBase NoSQL。小程序和 Web 统一调用 `/v1/xg/*` 专用业务 API；新集合保持客户端不可直接读写，服务端负责身份、关系、字段可见性、计分和预警校验。

选择理由：复用现有部署和存储，避免为四评另建一套身份和数据链路。代价是将交付包里的 SQL 函数、视图、RLS 和部分唯一索引的业务含义转成后端实现，不能直接执行原 SQL。

已排除本阶段引入 PostgreSQL 的路线。以后如需变更存储，应另做架构变更评审，不作为本次四评实现的隐含前提。

### 2.2 运行边界

| 能力 | 拟定落点 | 必须满足的要求 |
|---|---|---|
| API | 现有 CloudRun 服务中的独立四评路由 | 不向旧通用 `/rest/v1/*` 增加四评集合的任意读写入口 |
| 身份 | 复用服务端会话接口形态，补齐真实来访身份 | visitor_id/counselor_id 从可信会话解析；不能信任客户端传入身份、openid 或演示 ID |
| 授权 | 四评业务服务 | 每次读写校验周期、角色、对象归属；按角色使用响应白名单 |
| 计分与预警 | 独立、可测试的 Node 规则模块 | 不在页面复制公式，不由 LLM 决定分数或预警 |
| 数据 | 新增 xg_ 前缀的专用集合 | 与旧 PCOMS 数据并存；旧 ORS/SRS 不自动转换成七题基线 |
| 事务 | CloudBase 服务端数据库事务 | 作答成功、唯一名额占用、必要档案更新及持久化任务投递必须具有一致性 |
| 调度 | 独立的平台定时触发器调用受认证的 CloudRun 内部接口 | 不依赖容器常驻计时器；允许实例缩容至零。触发器资源在 T16/T17 配置 |
| 通知与 LLM | 持久化任务 + 可重试 worker | 外部调用放在数据库事务之外；失败不能丢掉已经接受的作答 |
| 本地验证 | 规则单元测试、API 测试、隔离云环境验证 | 内存/文件测试不能替代真实数据库的并发与事务验证 |

CloudBase 官方文档说明服务端 Node SDK 支持事务；同时限制事务中的条件查询方式、操作数量和执行时间。实现时应使用可直接定位的文档 ID，并在实际 SDK/环境上验证冲突和回滚行为。[事务文档](https://docs.cloudbase.net/database/transaction)

### 2.3 一致性约束

- “先查询有没有、再新增”不能作为并发唯一保证。为一段周期的一张卡、一个节次/随访轮次建立确定的提交名额键，并在事务中占用；失败尝试不占用成功名额。
- 填卡尝试 `client_event_id`、操作请求 `request_id` 与业务提交名额分开：尝试可经历拒绝与修正；同一操作的重试沿用请求键；成功名额保证一个业务位置只有一份有效答案。T10 契约见 [请求幂等与并发](t10-idempotency-concurrency.md)。
- 周期需要独立的版本/串行化锚点。更新作答、周期状态和跨卡组合判读时，不能基于事务外的过期查询结果直接覆盖新状态；具体读写协议留给 T04/T10/T13。
- 接受作答时同时写入必要的待处理任务记录，避免“答卷保存成功后进程退出、异步任务永远丢失”。确定性计分同步完成；跨卡组合更新必须可幂等重算。
- 事务内不发送通知、不调用 LLM。worker 重试、任务领取与超时恢复在 T17/T19 实现。

### 2.4 T01 验收

1. 当用户确认 NoSQL 路线时，后续设计应统一采用该存储，不再要求执行 Supabase DDL、RLS 或 pg_cron。
2. 当没有可信来访身份时，正式四评接口应拒绝操作；隔离演示账号只能用于测试数据。
3. 当单次提交发生并发或事务失败时，后续实现必须证明无重复有效作答、无部分写入和无任务遗漏。

本阶段确认架构和验收约束，不宣称事务、真实身份或调度器已经实现。

## 3. T02：咨询关系与周期

### 3.1 核心对象

| 标识 | 含义 | 约束 |
|---|---|---|
| visitor_id | 来访的稳定身份 | 可跨多次评估和咨询周期；不使用姓名或手机号自动合并身份 |
| assessment_id | 现有准入/匹配评估记录 | 是周期的来源引用，不是周期 ID |
| counselor_id | 咨询师身份 | 周期创建后不直接修改归属 |
| match_id | 一段独立咨询周期 | 服务于本次接口兼容；内部也用这一名称，避免再引入含义重叠的 case_id |
| session_id / session_no | 周期内实际会谈及其序号 | session_no 在周期内从 1 递增；一次会谈中的多张卡共享同一节次 |
| actor_id / actor_role | 实际作答或处理人 | M3 的被评估来访仍是 visitor_id，实际作者是咨询师 |

周期至少记录双方身份、来源评估、状态、开始/结案时间、创建来源及可选前序周期 ID。基线、重测、节评、结案、随访、预警、LLM 结果均关联 match_id；知情同意按来访及用途留痕，单案开关按周期保存。

### 3.2 生命周期草案

| 情况 | 处理 |
|---|---|
| 仅选择咨询师或提交申请 | 不自动视为 active 周期 |
| 咨询师/管理员通过服务端确认开始咨询 | 创建新 active 周期；要求申请已获准且真实来访身份已绑定。重复请求返回同一周期 |
| 联系状态变化、预约改期、短暂停诊但未结案 | 保持原周期；未发生的会谈不占用已完成节次 |
| 更换咨询师或正式重新匹配 | 关闭被替代周期并记录原因，创建新周期；不改写旧周期的咨询师 |
| 已结案后再次咨询，即使仍是同一咨询师 | 创建新周期，重新基线，节次从 1 开始 |
| 结案后 1/3 月随访 | 继续归属旧周期，不挪到新周期；须符合有效随访同意 |
| 录入错误需要修正 | 由有权限人员走留痕修正，不通过“重新开案”或覆盖历史隐藏错误 |

同一来访与同一咨询师不重复创建并行 active 周期；是否允许同一来访同时与不同咨询师开展独立服务，本草案不新增全平台限制，但数据与权限始终按周期隔离。

创建周期是需要新增的明确业务动作；旧页面的 `approved/contacted` 不直接触发批量历史建案，旧可变的 `selected_counselor_id` 也不是四评授权依据。

### 3.3 节次、基线与权限

- 每周期最多一份原始 M0，记 session_no=0；M2/M3 从第 1 节起，常规 M1 从第 2 节起。
- 首节距原始基线提交超过 7 天时补一次 M1，记 session_no=1。重测只更新该周期参照值，原始基线保留。
- 基线重测不是额外一节治疗观察；连续节评判定从常规 M1 开始，不把重测当作第二个独立观察点。
- 会谈已经完成但某张卡缺失时，保留真实节次，不把下一次有答案的会谈重新编号来隐藏缺口。
- 新咨询师只看自己的周期，不继承旧咨询师周期的原始作答、预警和 AI 结果。旧咨询师可按既有角色规则回看本人周期和其随访，不能读取新周期。
- 如将来需要转介交接，另行设计经授权的摘要共享；不默认共享整份历史。
- `follow_round` 的 1m/3m 是独立业务位置；结案与随访不参与会谈连续性判定。

### 3.4 T02 验收示例

来访 V 与咨询师 A 建立周期 M-A，完成 5 节后结案；之后与咨询师 B 建立 M-B。

1. 当 M-B 开始时，应允许重新填写基线和第 1 节卡片，不因 M-A 的记录冲突。
2. 当 B 查询趋势时，应只看到 M-B；A 查询时不能看到 M-B。
3. 当 M-A 的 1 月随访提交时，应更新 M-A，不更新 M-B 的结案或基线。
4. 当 V 以后再找 A 时，应新建 M-A2，不能覆盖 M-A。
5. 当重复确认同一次开始咨询请求时，应只创建一个周期。

## 4. T03：计分与预警规则

以下阈值取自 V3.2，作为待验证的工程复核规则；本文件不证明其测量学或临床有效性，不把预警名称解释成诊断或疗效结论。

### 4.1 分数定义

| 指标 | 公式/范围 | 用途 |
|---|---|---|
| 核心状态分 state_total | s1+…+s7，0–70 | M0/M1 主分、状态趋势、较基线差值 |
| 状态百分比 state_pct | state_total / 70 × 100 | 绝对低分条件；不随选修改分母 |
| ORS 对照分 ors_total | round((s1+s2+s3)/3+s4+s5+s6)，0–40 | 独立展示；沿用交付包公式，不与旧 PCOMS 原始 ORS 混成同一序列 |
| 附加分 add_total | s7，0–10 | 单独留存，同时仍是七题核心分的一部分；不加入 ORS |
| 选修稳定化分 stability_total | s8+s9+s10，0–30 | 本版三题整组开启/关闭，按周期配置；关闭时为 NULL，不是 0 |
| 补足分 supp_total | M0=b1+b2+b3；结案=e3+e4+e5；随访=u2+u3+u4，各 0–30 | 分别保存，不能仅凭同量程就自动做跨时点差值 |
| 资源分 resource_total | r1+r2，0–20 | 基线独立指标 |
| 解离档 dissoc_level | d1∈{0,1,2} | 独立规则，不入任何总分 |
| 感受卡 feel_total | f1+…+f4，0–40 | 联盟规则 |
| 对照卡 pro_total | p1+…+p6，通常 0–60 | 咨询师对照；首节 p6 例外见 4.6 |
| 双向差 diff_post | abs(feel_total/40×100 − pro_total/60×100) | 双方均有效且量程完整时计算；任一侧缺失为 NULL |
| 结案/随访主分 | 各自六题之和，0–60 | 不与七题状态分直接相减 |
| 服务评价 | v1+v2+v3，0–30 | 独立保存；o1 不计分 |

所有计分输入先按题库校验，不填补缺失值。阈值判定使用未四舍五入的数值，展示值保留两位小数；state_pct<30 可直接使用 state_total<21 判断。

每份事件保存规则版本、题目版本、实际题面与选修开启情况。动态 s7 的关注主题改变时应标注变更点；不把历史答案解释为针对新主题的回答。

### 4.2 参照值与连续窗口

- 参照值 ref_baseline = 本周期有效首节重测值，否则原始 M0；之后不随着每节状态自动漂移。
- “连续 N 节”指同一周期最近 N 个真实连续节次，每节均有对应卡片的有效提交。缺卡、拒绝或放弃均不补值，且不能跨缺节拼接连续窗口。
- M1 与 M2 的连续窗口各自判断；一侧完整不能补另一侧的缺口。
- “连续三节下降”定义为三次有效观察产生两次严格下降，三个节次必须相邻；不是三次下降、四个观察点。
- 低质量但通过数值校验的答卷照常保存，按原包进入规则判断并显示质量标记；不进入用于校准/调权的模型样本。无效答卷不计分、不触发分数预警。
- 补交历史卡片可使连续窗口重新成立，需要重算受影响结果并留痕；不得把补交当成新的咨询节次。

T14实现与验收见 [连续窗口与阈值配置](t14-windows-thresholds.md)：目标节冻结的策略统一解释整个窗口；配置修改创建新版本，不改写旧事件。l3_consecutive配置为N≥3时，单调下降检查全部N节；加速下降要求最后一跳达到阈值，且此前所有跳均未回升。

### 4.3 原始信号规则

| 规则 ID | 条件（默认阈值） | 原始等级 | 说明 |
|---|---|---|---|
| OUT-LOW | 当前 M1 state_total<21 | L3 | 独立触发；不等待连续两节低于基线 |
| OUT-DROP | 最近连续 2 节 M1 均满足 total−ref_baseline≤−7 | L2 | 使用固定七题核心分 |
| OUT-MONO | 满足 OUT-DROP，且最近连续 3 节 M1 严格单调下降 | L3 | 保留原包对这一路升级的连续下降前提 |
| OUT-ACCEL | 满足 OUT-DROP；最近连续 3 节中，本节较上节降≥7，且上节较再上节未回升 | L3 | 与 OUT-MONO 可同时命中，保留多项证据 |
| OUT-FLAT | 最近连续 4 节 M1 每节 abs(total−ref_baseline)<3 | L2 | 明确沿用“接近基线”，不是相邻两节变化小；不被联盟稳定规则降级 |
| OUT-SINGLE | 单节较基线下降≥7，但未满足更高等级规则 | L1 | 记录观察信号，不作为自动干预结论 |
| ALL-TOTAL | 最近连续 2 节 M2 总分均≤28 | L2 | 不跨缺失节次 |
| ALL-DIM | 最近连续 2 节 M2 每节至少一项≤3 | L2 | 两节可以是不同题目；保存每节具体命中项 |
| ALL-GAP | 同一节完整 M2/M3 的 diff_post≥15 个百分点 | L2 | 固定业务键去重，不取决于先提交哪侧 |
| STAB-SELF | 选修开启，连续 2 节 M1 每节至少一项 s8–s10≤3 | L2 | 开启之前的缺失选修不能当成 0 分 |
| STAB-PRO | 选修开启，连续 2 节 M3 的 p4≤3 | L2 | 与交付包的选修开关作用域一致 |
| DISSOC | 本周期 M0 的 d1=2 | L3 安全标记 | 按原包保留独立安全路径，不作诊断等同解释 |

无匹配信号的正常提交保留作答记录，不为其生成待处理提醒。已有准入 risk_level 只读引用，不由四评分数改写。

### 4.4 组合判读与提交顺序

组合依据 `(match_id, session_no)` 关联事件；每条信号保留自身 event_id，不能要求 M1/M2/M3 共用 event_id。

| 情况 | 拟定处理 |
|---|---|
| 仅收到 M1，尚缺 M2 或 M3 | 组合状态为待补齐；保留原始 L2/L3，不把缺失解释为稳定 |
| OUT-DROP 为 L2，M2 全部题目>3且总分>28，完整 M3 与 M2 差异<15 | 可以派生 L1 的组合展示等级；保留原始 L2 证据及原因 |
| 状态下降同时有联盟低分信号 | 保留 L2/L3，标注两条线同时命中；不输出“真恶化”等定性结论 |
| 状态下降同时有双向差异信号 | 保留原始级别，显示“双方评价存在差异”，不推定咨询师未察觉 |
| 已命中任意 L3 | 组合判读不得降级 |
| OUT-FLAT 停滞信号 | 不套用“状态下降＋联盟稳定”的降级分支 |

M1、M2 或 M3 任一有效提交/补交后，按同一组规则更新组合结果。后到数据不产生重复业务告警；原始信号、派生等级、证据版本和变更记录分开保存。

T13实现与验收见 [跨卡片组合判读](t13-cross-card-combination.md)：版本来源固定优先M1→M2→M3，作答和待重算标记原子保存，后到数据按周期重建受影响的结果并保留修订。本项只开放管理员计算审计，业务提醒展示仍由T15控制。

### 4.5 判定与提醒分离

计算、存储、展示、通知是不同动作。T03 确认信号计算口径，并不自动打开任何 L2/L3 通知或督导流程；全局/单案开关和安全线展示按 T15 另行实现和验收。

T15实现见 [阶段开关与回滚](t15-rollout-rollback.md)：安全线始终可见；全局或单案可开放L2，普通L3仅由全局开放；emergency_stop压住普通提醒和CST，单案不能绕过。collection_paused独立控制新开卡，已开始答卷允许完成。发送闭环仍由T17完成。

T17发送闭环见 [通知状态与重试](t17-notification-delivery.md)：未知发送结果不自动重试；服务商受理、站内存储、用户已读、咨询师确认和CST完成分开记录，安全短信失败须留站内提示和人工电话跟进要求。

### 4.6 已确认的补充产品规则

1. **首节 p6“较上节”没有比较对象。** 首节标记不适用，保留 p1–p5 的原始值；完整 pro_total/pro_pct 和基于六题的 diff_post 返回 NULL，首节不跑 ALL-GAP。不能伪造“持平=5”。第二节起恢复六题量程。p4 等单项仍可保存供后续连续判断。
2. **结案补足题的锚点与基线不同。** 原题 b1–b3 问当前状态，e3–e5 含“更亲近/更能应对”等变化表述。本阶段保存原题，基线、结案、随访分别展示，暂不生成三时点“同一把尺”的连线或差值；若以后要求可比曲线，应先统一题面和锚点并新增题目版本。
3. **“每次≤1分钟”与质量阈值存在冲突。** M0 为13题，按每题5秒计算，低于65秒就会标记低质量。保留每题5秒的质量标记阈值，取消统一的≤1分钟承诺，后续用试填数据调整；该阈值用于质量标记，不是禁止提前提交的倒计时。

以上三条已于 2026-10-25 经用户“都同意”确认，后续按此实现。
