# T19｜LLM 异步任务、校验与人工审核

日期：2026-10-25。状态：本地实现及专项验收完成。未部署、未新增真实云资源、未配置线上定时器、未调用真实模型或传输真实作答数据。

## 交付范围

- 有效作答与模型待办同事务提交，模型失败不丢失已接受的作答。
- 持久租约、有限重试、04:00补跑资格、旧回调隔离及分版本重跑。
- 现有服务的 OpenAI 兼容 `chat/completions` 适配器；未配置时保留待办。
- 固定数值白名单输入、严格结果校验、低质量样本排除。
- 独立结果/历史/权重建议；管理员审核、否决、手工修订及恢复辅助权重。
- 咨询师/管理员安全读取、任务队列管理接口及真实任务成功率统计。

沿用 CloudRun + CloudBase NoSQL，不执行原包 SQL，不引入 CloudBase 托管 AI 或更换模型服务。新增6个私有集合：`xg_llm_jobs`、`xg_llm_attempts`、`xg_llm_history`、`xg_llm_audit`、`xg_tag_weight_proposals`、`xg_tag_weights`；结果继续使用原有 `xg_llm_results`。集合声明总数42个，客户端直读/直写继续关闭。声明及索引尚未在真实环境创建。

## 作答、入队和处理

成功提交且 `quality_flag=ok` 时，以 `event_id` 为唯一任务ID，在作答、提交名额、档案、回执和审计的同一事务中保存 pending 任务。入队存储失败会回滚本次事务，客户端沿用原请求键重试，不会出现“已接受但没有待办”。外部模型调用不在这个事务内，也不阻塞作答响应。

rejected、abandoned、低质量提交都不创建模型任务。低质量数值仍照 T03 参与确定性计分/规则，不作为模型目标或其他任务的上下文。旧历史记录不会被自动批量补入队；需要补历史数据时应在 T21另行明确迁移范围。

| 状态 | 含义 |
| --- | --- |
| pending | 持久任务等待领取；未配置模型时保持此状态且不消耗尝试 |
| processing | 已领取租约，开始一次模型调用 |
| retry_wait | 可重试失败，等待 next_attempt_at |
| blocked | 有效同意、来访身份或采集开关不满足，等待重新核对；尚未调用时不消耗模型尝试 |
| failed | 本轮失败；仅明确可补跑的任务有 recover_at 和 recovery_eligible |
| review_required | 不安全输出、自动预算耗尽或管理员否决，转人工处理 |
| cancelled | 来源不再是符合资格的提交 |
| done | 校验通过的结果、历史、建议与任务终态已一致保存 |

运行器每次事务领取一个任务，固定 generation、attempt_id、lease_token；默认租约30秒，真实适配器单次超时8秒。结果写入时再次检查租约、generation、周期、来源、当前同意和采集开关。调用期间撤销或变更同意，结果不落为可用分析；重新满足条件后再尝试。结案不会将任务移至新周期，随访仍核对原周期的 followup 同意。

过期租约按未知调用结果计一次失败，并进入有限重试。LLM 与通知不同：这里没有对外发送消息的副作用，可以重算，但外部模型可能被重复计费；只保证结果落库的幂等及旧回调不能覆盖新状态，不宣称外部调用恰好一次。成功结果、不可覆盖历史、权重建议、尝试状态和任务终态在同一事务内保存。落库失败不伪装成服务商失败；同一有效回调可重试，进程退出后可由租约恢复。

## 输入与版本

第一次领取时冻结输入，重试和自动补跑沿用该快照：

- 当前卡片的适用数值题；同一周期、同一节次已提交且质量合格的 M1/M2/M3，以及最多近三个相邻节次范围内的 M1 数值。
- 趋势保留真实节次，缺卡不补值、不重编号，不把首节重测当成治疗趋势。
- M0、结案、服务评价和随访按自己的卡片分析，不拼接跨阶段同量尺分数。
- 不传姓名、联系方式、身份证、业务身份ID、周期ID、事件ID、逐字稿、开放文本、动态关注点原文、备注或完整题面。连哈希身份也无需提供。
- 有数据才允许模型输出对应维度分。ORS/目标进展需要状态卡；联盟需双方卡片且不是缺 p6 的首节；稳定度需咨询师 p4 或实际存在的选修数值。其余维度必须为 `null`，不得用0或猜测替代缺失。

与原包“始终返回四个数值”相比，这里明确支持四键齐全但缺证据的值为 null，解决缺卡时被迫编造维度分的问题。结案/随访可以仅有数值摘要而无这四个维度分。

任务保存输入摘要哈希、来源事件与冻结依据哈希、辅助权重版本、模型名及 `prompt_version=xg-analysis-t19-v1`；这些内部来源信息不发送给模型。新卡后来补齐不会静默改写已领取任务的快照；后提交卡片的任务会有自己的快照，必要时管理员可明确重新分析。模型名或提示词版本与已冻结任务不一致时停止自动调用，须由管理员建立新 generation。

## 输出及读取

兼容适配器接收完成状态为 `stop` 的文本响应；网络响应上限64 KiB，输出 JSON 文本上限16 KiB。可剥离单层完整 JSON 围栏；不接受围栏外解释、额外字段或无效 JSON。

| 字段 | 校验 |
| --- | --- |
| summary | 非空，最多60个字符，中性描述 |
| dim_scores | 恰好 ORS/联盟/稳定度/目标进展四键；有证据为有限0–100数值，无证据必须 null |
| suggest_actions | 最多2条，每条非空且最多200字符 |
| tag_weight_adjust | 最多3条、标签不重复；仅限有证据的四个维度；delta在±0.2内，reason非空且最多200字符 |

文本先进行兼容字符规范化、移除零宽/方向控制字符，再检查医疗化/诊断/药物等禁用措辞及联系方式、链接等模式。不安全输出直接转 review_required，不保存原始文本或维度分；普通 JSON/结构校验失败可以有限重试。此过滤和提示词是工程防线，不能证明任何通用模型具备临床有效性，也不是完整的语义安全审核；管理员可以否决已通过机器校验的结果。

`GET /v1/xg/llm-results?match_id=...` 沿用 T06 的角色和周期授权。来访始终无权读取；咨询师仅本人周期。T19结果再次通过校验后，返回 `advisory_only=true`、generation、weight_revision、review_status及白名单摘要/维度/建议，不返回内部输入、权重调整理由、联系信息、租约或密钥。被否决或已被重跑替代的结果隐藏。结果存于独立集合，主事件分数、档案、确定性预警和阈值均不被 LLM 改写。

## 重试与降级

- 5xx、超时、网络异常、JSON或结构校验错误：第一次失败后至少1秒、第二次失败后至少4秒重试；由外部扫描触发，不在进程里 sleep。
- 每个 generation 先最多3次尝试。第3次可重试失败后成为 failed，记录下一次上海时区04:00的补跑资格。
- 恢复扫描将符合资格的失败任务重新排队，第4次失败后等4秒，第5次仍失败则 review_required；不会无限日复一日重试。
- 4xx（含429）不自动补跑，直接 failed；不安全输出直接人工处理。存储/来源异常、具体失败原因和任务待办可供管理员核对，脚本返回计数供平台告警。
- 未配置或配置无效时，不调用模型、不消耗尝试、不影响正常提交；扫描报告 configured=false。不得假造成功结果。
- 服务商响应体、请求头、URL中的秘密及原始异常不写入任务/审计。只保存固定安全错误码。历史尝试保留跨 generation 的累计调用数。

1秒、4秒是“最早可重试时间”，实际执行取决于外部调度频率。每日04:00也只是恢复资格和建议调度时点，本次没有启用真实定时器。

## 人工审核与辅助权重

这里的“权重”是**本周期 LLM 辅助分析倍率**：四个维度默认均为1，允许0.1–2；提示词基准权重仍为0.35/0.35/0.20/0.10。批准不会修改七题核心分、ORS确定性公式、主规则阈值或其他周期。为避免将自由标签或个人标签写入生效配置，当前标签仅允许上述四个维度。

模型成功时建议写 pending，永不自动应用。批准需同时满足：建议修订未变、结果仍为当前 generation 且未否决、任务 done、当前辅助权重版本等于生成建议时的版本。多个建议竞争同一个权重版本时只能一个成功，其他需刷新/重新分析；不能悄悄叠加旧建议。批准、拒绝、有效权重及审核审计原子提交，相同请求重放不重复应用。

管理员还可手工设置完整的四维辅助倍率，并说明原因、提供修订号和请求键。审计保存修改前后值，可用该入口恢复默认或先前批准的配置。否决一份模型结果会隐藏该结果；若其建议此前已批准，需要管理员通过此入口明确修订/恢复辅助权重，不自动改写已审阅的权重历史。

人工重新分析必须提供 reason、expected_revision、request_id；只允许已完成/失败/待审核/阻断/取消状态，不能抢占正在调用的任务。新 generation 重新冻结输入和模型信息、获得新的5次预算；原始任务创建时间、累计尝试、旧结果历史和审核记录保留。旧结果立即标记 superseded，旧建议不能再批准，直到新结果成功才提供当前结果。

本项交付审核 API 和队列读取接口；不宣称已经新增管理员审核网页，也未安排每周审核提醒。

## 接口

所有管理员接口都只接受有效管理员会话，拒绝其他角色；请求字段采用白名单。

| 方法与路径 | 参数/用途 |
| --- | --- |
| GET `/v1/xg/admin/llm-jobs` | 可选 status/after/limit（1–100，默认50）；安全队列元数据，游标分页 |
| GET `/v1/xg/admin/llm-jobs/:event_id` | 当前任务、当前代建议、结果审核状态与辅助权重版本；不返回模型输入快照 |
| POST `/v1/xg/admin/llm-proposals/:proposal_id/review` | decision=approved/rejected、expected_revision、expected_weight_revision、reason |
| POST `/v1/xg/admin/llm-jobs/:event_id/review` | decision、generation、expected_revision（结果审核修订）、reason；已否决结果不能直接批准恢复，须重新分析 |
| POST `/v1/xg/admin/llm-jobs/:event_id/reprocess` | expected_revision（任务修订）、request_id、reason |
| GET `/v1/xg/admin/llm-weights/:match_id` | 本周期生效辅助倍率及修订 |
| POST `/v1/xg/admin/llm-weights/:match_id` | 完整 weights、expected_revision、request_id、reason；手工修订或恢复 |
| POST `/v1/xg/jobs/llm-run` | scheduler专用凭据；仅limit，1–5，默认5 |
| POST `/v1/xg/jobs/llm-recover` | scheduler专用凭据；仅limit，1–100，默认50 |
| POST `/v1/xg/internal/llm-score` | scheduler专用凭据；仅event_id，处理已有任务，不允许客户端上传模型输入/分数或任意地址 |

普通管理员会话和 matching 凭据不能调用专用调度入口。API输出及错误继续 no-store。原包统一 XG_SERVICE_TOKEN 已按 T16/T17 契约改为独立 `XPG_SCHEDULER_SECRET`。

## 配置与执行

运行环境需注入：

| 变量 | 用途 |
| --- | --- |
| XG_LLM_BASE_URL | HTTPS兼容服务的基础路径，如 `https://model.example.test/v1`；适配器追加 `/chat/completions`，拒绝用户名/密码、查询参数、fragment及重定向 |
| XG_LLM_API_KEY | 仅在服务端请求头使用，不入库、不打印 |
| XG_LLM_MODEL | 服务方明确支持的模型名，不预设任何真实供应商或模型 |
| XPG_API_BASE | 调度脚本访问的CloudRun地址 |
| XPG_SCHEDULER_SECRET | 已有独立调度服务凭据 |

```bash
node scripts/run-llm-jobs.cjs run
node scripts/run-llm-jobs.cjs recover
```

run建议周期性执行，recover建议每日上海时区04:00执行。脚本默认每次最多10批，run每批5条以控制8秒模型超时下的请求时长，recover每批50条；禁止重定向，只允许HTTPS（本地回环HTTP用于测试）。摘要不输出事件或来访标识；错误、失败、待人工审核、未配置或批次预算用尽但可能剩余时退出码为1。平台需接收退出码/摘要并设置实际告警，本次只提供可调度入口。

## T18统计接续

统计 schema_version 更新为 `stats-t19-v1`。`metric=llm_success` 仅读取 `xg_llm_jobs` 的必要状态投影：

- `llm_success_rate`：区间内创建的不同合格任务中，当前done且在as_of前完成的任务 / 全部该群体任务；低质量答卷未入队，不伪造任务；重试或换generation不增加分母。
- `llm_status_rates`：pending/processing/retry_wait/blocked/failed/review_required/done/cancelled各状态比例。
- `llm_failure_reasons`：failed与review_required任务中，human_review/output_validation/timeout_network/upstream/other各类比例，只用固定安全错误类别。

全部沿用 T18 至少5名不同来访及非零分子/补集门槛；不足时不返回值或计数。保留有界分页与超限503，不从结果集合倒推成功率。历史区间反映截至本次读取的状态，管理员否决或重新分析可改变比例；不是冻结审计快照。
