## 线上实际链路与源码归属

本轮发现线上静态页面比原 `web/` 更新，实际调用 `xpg-rest`，四评页面调用旧 `xg-api`。为保留已经上线的照片、准入、短编号及审批功能，先下载并记录源码哈希，再做定点修复；没有用仓库旧页面覆盖整站。

- `legacy-web/`：本轮修改的线上页面与共享配置；只上传列出的 7 个文件。
- `cloudfunctions/xpg-rest/`：实际在用的 REST 云函数，管理员密码改由环境变量读取，原密码保持不变。
- `cloudfunctions/xg-api-legacy/`：旧四评云函数的安全兼容版本，实际函数名仍是 `xg-api`。沿用旧数据格式，没有转换历史分数或补造咨询周期。
- `cloudrun/legacy-gateway/`：旧 `xiaopingu-api` 地址的兼容转接服务。网页跳转到现有静态站点，旧 REST 请求转发到已修复的 `xpg-rest`；本服务不含数据库 SDK，不直接读写数据库。
- `cloudrun/xiaopingu-api/`：新版四评后端，继续部署到独立预览服务及独立集合。

## 已实现的修复

| 项目 | 修复与验证边界 |
| --- | --- |
| 档案匿名修改 | 旧 REST 要求本人编辑凭证或管理员身份；公开咨询师 ID 不能授权修改。 |
| 咨询师自行审批 | 本人只能修改资料白名单；审批、启用、角色、身份绑定等字段拒绝混入，整次请求不落库。管理员审批仍保留。 |
| 跨咨询师访问 | 查询始终先限定实际归属，再应用客户端筛选；省略条件、替换来访者或周期、伪造个案开关均不能获得权限。 |
| 伪造匹配审批 | 来访者可提交申请，但不能写审批结果；仅所属且已审核的咨询师或管理员可审批。旧四评桥接要求真实已有的审批周期。 |
| 匿名临床写入 | 保留公开初评及注册；禁止通过旧通用入口匿名写 visitor_users、sessions、pcoms_ratings。既有数据未删除。 |
| 浏览器令牌边界 | 只向确切 API 源站和路径附加令牌；保留请求明确指定的身份；咨询师登录后清除旧管理员会话，避免角色混用。 |
| 默认演示身份 | 线上不再提供默认四评令牌，演示账号不访问真实记录；咨询师使用本人编辑码。原管理员密码继续可用。 |
| 短编号 | 8 位号仅用于查找；解析需原设备保存的完整评估凭证。完整评估链接仍可用。跨设备仅有短编号时会提示使用完整链接，不返回 UUID 能力凭证。 |
| 咨询师四评入口 | 新按钮先向服务端核对所属来访及已审批周期，再设置个案上下文并进入 C1；令牌不写入 URL。未完成前置条件时显示具体提示。 |
| 旧 session 页面 | 增加迁移说明、咨询师登录和“我的评估”入口，保留历史记录，不自动转换成新基线。 |
| 微信扫码 | 未配置时明确返回未开通，不生成模拟身份或无意义扫码会话；回调增加签名校验，会话及绑定检查过期。真实账号与真机验收延期。 |
| 后台任务 | 旧自动随访、动态题刷新、LLM stub 返回关闭状态，避免无真实调用却标记成功。新增独立随访适配器默认禁用，未部署 cron，也不会调用通知发送。 |
| 旧数据整理 | 只读扫描 55 条申请的 ID、时间和显式测试标记；没有一条带明确测试标记，无法确认图中“46 条测试申请”。全部保留。 |

风险复查卡继续保留；恢复预测曲线关闭，动态关注点仍由人工维护。
