## 连续窗口语义

观察节数N表示N个真实连续节次，不是N次变化。必须每节都有该卡片成功且可复算的答案；不对稀疏数据排序后直接取最后N条。

M1从第2节起形成常规窗口；M2/M3从第1节起。首节重测可提供参照基线，但不能充当一个常规观察。选修稳定化还要求窗口内每份事件的冻结选修开关均为开启，关闭或未开启的事件会中断这一路判定，不能以0分代替。

过大的窗口先与实际可用行数比较，不创建庞大的缺失节次数组。没有足够历史时不命中连续规则，独立OUT-LOW或单节信号仍按自己的条件计算。

| 规则 | 边界及窗口 |
| --- | --- |
| OUT-LOW | total/70*100严格小于l3_low_pct；默认20分命中、21分不命中；不依赖下降或连续窗口 |
| OUT-DROP | 最近N节每节相对参照下降≥outcome_drop_abs，等号命中 |
| OUT-MONO | 先满足OUT-DROP；最近l3_consecutive节严格下降，每一步都必须下降，持平不算 |
| OUT-ACCEL | 先满足OUT-DROP；最近l3_consecutive节中最后一跳下降≥outcome_drop_abs，此前所有跳均不得回升；此前持平允许 |
| OUT-FLAT | 最近N节每节距参照的绝对差严格小于outcome_flat_delta，等号不命中；不是相邻两节变化小 |
| OUT-SINGLE | 单节下降达到阈值，且没有更高等级的OUT信号 |
| ALL-TOTAL | 最近N节M2总分均≤alliance_total_max |
| ALL-DIM | 最近N节每节至少一题≤alliance_dim_max；允许不同节命中不同题，并保留题号 |
| ALL-GAP | 完整同节M2/M3的差异≥diff_post_warn；先用未取整比例判定，再格式化展示 |
| STAB-SELF/PRO | 窗口中每节选修均开启，指定项≤stability_item_max |
| DISSOC | M0的d1恰好等于2，不并入核心总分 |

各规则窗口独立。修改OUT-DROP的N不会替代l3_consecutive，升级时两个前提都须满足。低质量但合法的答案继续参与判定并携带质量标记。

## 参数契约

| 参数 | 允许值 | 默认 |
| --- | --- | --- |
| outcome_drop_abs | (0,70]，有限数值 | 7 |
| outcome_flat_delta | (0,70]，有限数值 | 3 |
| outcome_drop_consecutive / outcome_flat_consecutive | ≥2的安全整数 | 2 / 4 |
| alliance_consecutive / stability_consecutive | ≥2的安全整数 | 2 / 2 |
| l3_consecutive | ≥3的安全整数 | 3 |
| alliance_total_max | [0,40] | 28 |
| alliance_dim_max / stability_item_max | [0,10] | 3 / 3 |
| diff_post_warn | (0,100]个百分点 | 15 |
| l3_low_pct | (0,100]% | 30 |

安全整数上限为9007199254740991；不另设小窗口硬上限。分数/比例阈值可用小数，但窗口长度必须为整数。最大值阈值允许0，用于“仅0分满足”的精确口径；下降差、停滞宽度和百分比阈值保持正数。

拒绝字符串数字、布尔、null、数组、对象、NaN/Infinity、超量程、未知字段、空变更以及不完整的全量定义。默认参数未改变。此接口只调整上述阈值，不调整题库、计分公式、量程、质量规则或同意文案。

## 管理员接口

`GET /v1/xg/admin/rule-thresholds`

返回当前revision、item_version、rule_version、完整thresholds、机器可读parameters约束、发布人/时间及最近变更原因。

`POST /v1/xg/admin/rule-thresholds`

```json
{
  "rule_version": "rules-reviewed-v2",
  "expected_revision": 1,
  "thresholds": {
    "outcome_drop_abs": 8,
    "l3_consecutive": 4
  },
  "reason": "经审阅后调整工程复核参数"
}
```

示例仅说明接口格式，不代表已发布这些值。thresholds是非空局部补丁，未提供字段继承当前版本。rule_version必须使用新的版本号；expected_revision取自GET结果。reason为非空且不超过500字符的变更原因。published_by来自已验证管理员会话，客户端不得传入。

新规则文档和当前发布指针在同一事务保存，保留前一版本及原文、来源修订、变更补丁、原因和操作者。并发发布时只有符合当前revision的一方成功，另一方409；不会留下半个规则版本。

- 首次成功201；当前头版本上的相同请求重试200，不再次增加revision。
- 同版本改内容、复用旧版本或试图重新激活旧版本409。
- 新版本使用过期expected_revision返回409 `XG_VERSION_CONFLICT`。
- 参数不合法400 `XG_RULE_PARAMETERS_INVALID`；无实际变化409 `XG_RULE_NO_CHANGE`。
- 来访/咨询师403，未登录401，不开放DELETE/PATCH，也不接受查询参数。
- GET/POST响应均no-store；不返回完整题库、原始答案或凭据。

## 参数生效与历史保护

发布只写规则版本及发布指针，不修改已开始/已提交事件，不替换已有basis，也不自动创建历史重算任务。新开始的卡片捕获新版本；已开始的卡片继续按原版本完成。

沿用T13，同节组合策略来源固定优先M1→M2→M3，与到达顺序无关。目标节的策略阈值统一应用于其整个连续窗口，包括窗口内较早版本的合法数值；每个证据事件仍保留自己的basis_ref。不会逐节使用不同阈值拼成一个不可解释的窗口。

例如第2/3节冻结下降阈值7；随后发布8，不改写第3节结果。第4节新卡选择阈值8时，其判定将第3/4节的历史分数统一与8比较，实际参数留在第4节结果中。

此次完整窗口修正及证据格式升级使用组合引擎 `xg-combination-t03-v2`，计分引擎仍是原来的 `xg-core-t03-v1`。已有v1组合历史不覆盖；后续实际重算产生v2修订并保留原修订。本项没有批量回填历史。旧数据若曾使用如今不受支持的参数，会明确停止重算；需先核对并通过可信完整版本发布路径修复，不静默夹取阈值。
