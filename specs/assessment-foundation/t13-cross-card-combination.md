## 交付范围

组合按 `(match_id, session_no)` 关联成功的M1/M2/M3，三张卡保留各自event_id。新增确定性计算模块、持久重算状态、原始信号、组合结果、不可覆盖的变更历史，以及管理员审计入口。

为使组合逻辑可实际运行，本项接入T03原始信号的基础计算：OUT-LOW/DROP/MONO/ACCEL/FLAT/SINGLE、ALL-TOTAL/DIM/GAP、STAB-SELF/PRO及DISSOC。T14仍负责连续窗口、配置参数及阈值变化的完整专项验收，不因本项基础实现而提前勾选。

## 组合规则

| 情况 | 结果 |
| --- | --- |
| 只收到M1，或M2/M3任意缺失 | pending_cards，保留原始等级，不把缺卡当作稳定 |
| 常规M1存在但尚无可用基线 | baseline_pending=true；三卡齐全时状态为pending_baseline，不猜测相对下降 |
| OUT-DROP=L2，M2总分>28、各题>3，完整M3与M2差异<15个百分点 | 可以派生L1；原始OUT-DROP仍为L2，原始证据不覆盖 |
| 有任何L3 | 保留L3，包括独立安全线，不降级 |
| OUT-FLAT | 保留L2，不套用下降＋联盟稳定分支 |
| 独立联盟或稳定化L2同时存在 | 独立信号继续保留，不能随OUT-DROP一并降级 |
| 同节M2/M3差异≥15个百分点 | 产生一个固定业务ID的ALL-GAP，保留两侧不同的事件ID |
| 首节M3的p6不适用 | diff_post=null，组合not_comparable，不产生ALL-GAP |
| 全部无信号 | 原始/展示等级均null，signal_ids为空；没有待发送通知或待处理告警 |

差异判定使用交叉相乘的整数总分：`abs(M2_total*60 - M3_total*40)*100 >= threshold*2400`。展示diff_post才保留两位小数，判定不用四舍五入后的百分比。

缺节中断原始连续窗口；拒绝/放弃事件不进入窗口；session_no=1的基线重测不作为常规M1观察点。原始基线与成功重测来源按T12语义选择，后续普通M1不改变参照。

M0的DISSOC采用周期安全信号ID，在各节结果中引用同一个ID；不会因多张卡到达产生多个安全告警身份。没有将四评分数写回旧准入risk_level，也没有输出“真恶化”“咨询师未察觉”等定性结论。

## 版本与证据

同节组合的规则来源固定按M1→M2→M3优先选择，基线记录使用M0；优先级与提交顺序无关。结果记录组合引擎 `xg-combination-t03-v1`、策略来源event_id、rule_version/rule_hash，以及每张证据卡自身的basis_ref和quality_flag。

当前实现只使用事件已经冻结的规则，不读最新发布版本来改写历史解释。不同规则版本的卡片同时存在时，仍保留各卡的来源，依上述固定策略计算；后到更高优先级卡片引起的结果变化会新增修订。

每个原始信号具有 `hash(match_id, signal_session, rule_id)` 业务身份。ALL-GAP以同节M2为锚点，证据中同时保留M2/M3；OUT-DROP等信号以其M1为锚点。原始等级、派生展示等级、降级原因、证据引用及变更历史分别保存。后续通知实现应消费稳定信号ID及结果修订，不应把每次重算当作新的业务告警。

输入先通过T12历史复算检查。缺历史依据、归属异常、原始分数与冻结依据不一致时停止重算，不生成猜测结果。低质量但合法的答卷仍参与规则，保留质量标记。

## 持久重算和一致性

新增4个私有集合，总清单现为26个：

| 集合 | 主键与用途 |
| --- | --- |
| xg_combination_jobs | match_id；单周期重算generation和完成generation |
| xg_raw_signals | hash(match_id,session_no)；当前原始信号及策略依据 |
| xg_session_combinations | 同上；当前组合等级、缺卡状态及来源 |
| xg_combination_history | hash(match_id,session_no,revision)；追加式原始/组合快照 |

提交事务原子保存答案、成功名额、档案、事件审计、请求回执及待重算generation。事务提交后立即重算该周期，保证历史补交和迟到基线可更新后续节次，而不只更新补交所在节。

重算在事务外读取已分页的事件集合，并用周期version检查快照一致性；每一节的原始信号、组合结果及历史在一个小事务内保存。发布前再次检查周期version与job generation，旧快照不能覆盖新结果。全部节次完成后才确认job完成；中途失败时保留pending，最新读取不能把部分结果当作完整最新结果返回。

相同结果的内容指纹不变时不增加修订；重复提交、重复执行及并行重算不会重复追加历史。历史补交即使不改变等级，只要证据改变也新增修订，原修订保留。

提交后的重算失败返回503 `XG_COMBINATION_PENDING`，其含义是**作答已经保存，组合判读尚待恢复**，不能理解为作答回滚。客户端沿用原request_id重试，先读回原提交回执，再继续重算。管理员读取最新组合也会恢复pending任务。服务内部还提供 `createCombinationRepository(store).refresh(match_id)` 供后续调度器调用；本项没有安装后台定时扫描。

如果进程恰在保存答卷后退出，pending仍在库中，不会丢失重算需求；下一次原请求重试、相关成功提交或管理员最新读取均可恢复。周期持续变化超过3轮时返回503，保留pending，避免无界循环。

可信低层导入不自动创建这些任务；旧数据应在T21迁移联调时先核对依据与分数，再安排重建。本项没有对旧环境做批量回填。

## 管理员审计接口

`GET /v1/xg/admin/session-combination?match_id=...&session_no=3`

可加 `revision=1` 查看指定历史修订。返回session_no、revision、historical、raw和combined；包含必要的数值证据/来源引用，不返回原始作答正文、完整题库、凭据或请求头。数据指纹、冗余归属和当前结果修订均会校验，损坏结果不会直接透传。

仅管理员可调用；来访、咨询师均返回403，未登录返回401。参数非法/重复为400，记录不存在为404，不开放POST修改。响应no-store。查询最新结果可能恢复派生数据的待办，但不更改任何原始答卷。

这里提供的是计算审计入口，不是业务提醒列表。咨询师提醒展示、阶段开关、安全线展示和紧急停用统一由T15接入；发送、确认和CST闭环由T17等后续任务完成。本项不新增消息发送。
