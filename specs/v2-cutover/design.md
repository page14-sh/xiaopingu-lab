# 技术与页面方案

## 数据区

新增独立正式前缀 `xg_v2_<release>_`，不复用已有 `xg_preview_*`，也不覆盖旧 canonical 集合。保留全部源业务记录的不可变 JSON 与 SHA-256，另生成新版可操作的身份、准入、咨询师和待处理申请。临时微信登录会话只备份，不恢复为可登录会话。

旧答卷无冻结依据，保留在历史集合，不放入新版事件成功名额、基线、连续判定、通知或 LLM 队列。无法可靠连接的记录列入管理员历史核对区。没有进行中咨询，因此不自动创建新版 active 周期。

## 身份与入口

用户已确认：新旧数据统一迁入新版并在同档案展示；旧完整评估链接只交换为 xg-history 只读会话，不能签署新版同意或填卡。旧来访者使用独立随机 256 位凭证（数据库只存哈希）；明文保存在本机私有交付文件，由用户核对身份后交本人。新来访者首次提交前由浏览器生成独立凭证并保存，服务端以事务绑定身份。本人咨询师编辑码仍换取过期角色会话。过渡来访身份标为 intake-receipt，不冒充 wechat-cloud。短编号仍需要完整历史凭证。

现有初评、咨询师资料、管理工作台以兼容接口接入新版数据库；新版四评页面直接使用冻结 form、版本化 consent、match_id、event_id 与 request_id 契约。所有按钮和静态配置指向同一正式后端。旧入口保留并转接；切流后旧服务不得继续向旧集合新增业务数据。

## 页面规范

目的：让现有用户保留入口与身份凭证，使用新版流程并能查阅明确标注的旧历史。

自然暖绿风格，沿用既有 `#5C7A52`、`#46603E`、`#FAF9F6`、`#2E2E2C`、`#E6E3DC`，字体 PingFang SC/Hiragino Sans GB/Microsoft YaHei。保留既有 640px 移动端单列、顶部导航和卡片组件；这是已有设计约束，不为本次迁移额外改版。

表单从服务端冻结题面生成；历史、新作答分区；错误明确保留用户输入并区分可重试、需重新同意、权限不足。来访者不显示四评分数、预警、咨询师 M3 原始答案。咨询师及管理员只显示对应权限的数据。

## 迁移与切流

只读盘点 → 私有快照 → 纯转换预演及异常统计 → 合成与隔离真库测试 → 新正式区导入并逐记录校验 → 最终写入暂停和补差核对 → 页面/网关切流 → 角色与只读历史验收。

旧库保留；迁移有确定性文档键和校验账本。目标已有记录与计划不一致时停止，不强行覆盖。若切流后已有新写入，恢复不能直接指回旧数据库而丢弃这些写入，应先暂停采集再处理。
