## 初始状态

只创建了账号和已经完成入驻审核的测试咨询师。交付给你的来访者没有初评、没有匹配申请、没有审批、没有咨询周期，也没有四评答卷。验收使用另一套独立身份和 8797 端口，不占用你的演示账号。

## 你实际操作的顺序

1. 首页用 `demo_visitor` 登录，完成原平台准入筛查、同意说明、基本信息、主诉和程度评估。
2. 初评报告生成并保存后，推荐列表会出现本组测试咨询师。演示区只开放这一位可匹配咨询师，仍走原匹配算法；分数不会被强制改成 100%。如选择危机红线答案，仍会按平台规则阻止匹配。
3. 在推荐卡点击“申请匹配”，填写合成姓名和联系说明，提交申请。此时才真正产生待审批申请。
4. 在顶部“切换演示账号”用 `demo_counselor` 登录，进入原咨询师工作台，在“匹配申请”中查看、通过或拒绝。通过后才创建新版咨询周期。
5. 咨询师在“我的来访”中进入四评；来访者从“我的评估/咨询过程记录”进入同一个周期。各自确认所需说明、填写各自卡片。
6. 在顶部“切换演示账号”用 `demo_admin` 登录原运营后台，查看咨询师、初评和匹配申请；“循证咨询”查看新版周期及具体四评结果。

第一节专业卡的 p6 不适用，总分为空是预期。来访者不展示四评分数；咨询师和管理员按权限查看。聚合统计的“样本不足”不影响查看具体测试个案。

结案及随访按真实业务时间执行，不自动伪造随访日期。真实通知和 LLM 均关闭。

## 启动与边界

- 本机服务：在仓库根目录运行 `npm run start:demo`。
- 首次生成固定账号：`npm run demo:accounts`。已存在时不会重置账号。
- 以前的 `journey.html` 直接跳回平台首页；旧的一键准备申请、自动切换身份和新建轮次接口已停用。
- 正式服务的 `/auth/account` 校验演示账号，再调用固定的 preview 认证接口。带 `xpgdemo.` 路由前缀的令牌只发往测试 API；前缀本身不授予权限，仍由测试后端核验签名与角色，失败不回退正式数据。
- “退出演示”恢复原正式会话与草稿。演示管理员仅查看测试区；正式管理员的统计不会混入演示记录。
- 只有独立测试数据区参与，正式真实数据不改动。公共网站的默认域名限制与此账号演示环境分开处理。
- 平台验证码由操作人完成；不通过脚本跳过。
